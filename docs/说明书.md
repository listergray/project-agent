## 1. 产品简介

`project_agent` 是公司预研项目 **「项目进度管理智能 Agent 平台（Java 微服务 + Python AI 编排）」** 的原型验证工程。它把两个典型场景落地为可运行、可浏览器演示的 Agent：

| 演示 | 名称 | 干什么 | 编排方式 |
| --- | --- | --- | --- |
| **RAG 知识库** | 企业资源知识库 RAG + Agent | 用自然语言问制度/流程/数据，支持「查文档 + 查实时业务库 + 导出」 | LangGraph 7 节点导入 + 7 节点检索 + 3 个 Function Calling 工具 |
| **代码助手** | 代码助手 AI 编程提效 Agent | 一句自然语言需求 → 自动产出 Java 代码 + 单测 + 接口文档 | LangGraph 5+1 节点流水线 |

**特点**
- 不依赖真实 LLM Key 也能 100% 跑通（每个 LLM 节点都有内置 fallback 模板）。
- 配置 Key（DeepSeek 等 OpenAI 兼容）后自动切换为高质量模型回答。
- FastAPI 统一 HTTP 入口 + 静态展示页，开箱即演示。

## 2. 环境要求

## 3. 快速启动（5 条命令）

```powershell
# 1. 建虚拟环境并装依赖（首次约 3~5 min）
cd E:\ai-pro\project_agent
python -m venv .venv --prompt project-agent
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"

# 2. 配置环境变量（把 LLM_API_KEY 改成你的 Key；不填也能跑 fallback）
Copy-Item conf\.env.example conf\.env
notepad conf\.env

# 3. 启动中间件（RAG 知识库 向量检索需要；代码助手 可跳过）
.\docker\up.ps1

# 4. 跑通两个智能体
rag-import          # 灌库：data/samples 三份手册 → Milvus（约 306 chunks）
rag-chat --presets  # 跑 5 个预设问题，看 3 个工具如何被调用
copilot-run             # 跑 代码助手 5+1 流水线，生成 Java/XML/测试/文档

# 5. 启 HTTP 服务（可选，做浏览器演示）
agent-api              # 等价于 uvicorn project_agent.api.server:app --port 8080
```

> 零依赖最快验证：直接 `pytest -q` 跑 5 条冒烟单测（约 10s 全绿），再用 `from project_agent.tools.rag_tools import *` 单独玩 3 个工具。

## 4. 使用 RAG 知识库（企业资源知识库）

### 4.1 灌库（导入流水线，7 节点）
`rag-import` 会读取 `data/samples/*.md`，依次执行：解析 → 读文件 → 清洗 → 语义分块 → LLM 抽 Item → BGE 编码 → Milvus 写入（双层索引 `kb_item_names` + `kb_chunks`）。

### 4.2 问答（检索流水线，7 节点）
`rag-chat --presets` 跑 5 类预设问题，覆盖三种意图：

| 编号 | 类型 | 示例 | 触发能力 |
| --- | --- | --- | --- |
| Q1 | 纯检索 | 固定资产入库流程怎么操作？ | 向量召回 + Rerank |
| Q2 | 纯查库 | FS-2024-0876 现在有多少库存？ | `query_resource_by_code` |
| Q3 | 模糊匹配 | 帮我查陈昊的工号和岗位 | `fuzzy_match_resource` |
| Q4 | 混合+导出 | 导出一份公司工作站/笔记本库存清单 | `fuzzy` + `export_to_excel` |
| Q5 | 财务 | FIN-INV-2024-001 是什么单据？金额多少？ | 工具 + 合规原文引用 |

### 4.3 三个 Function Calling 工具
- `query_resource_by_code(asset_code)`：按编码精确查资产/员工/财务记录。
- `fuzzy_match_resource(keyword, top_k=5, module=None)`：编辑距离 + 同义词加权模糊匹配。
- `export_to_excel(rows, filename)`：把结果写成 CSV（UTF-8-BOM）放到 `output/`。

> 详细能力定义见 `docs/SKILLS.md` 的 **S2 / S3 / S4**；调用约束（轮次、数据来源、幻觉红线）见 `docs/RULES.md`。

## 5. 使用 代码助手（代码助手 编程提效）

`copilot-run` 跑 **5+1 节点**流水线：需求拆解(N1) → 代码生成(N2) → 审查重构(N3) → 单测生成(N4) → 接口文档(N5) → 落盘(N6)。全部在 `output/copilot_XXX/` 下产出：

- `InventoryController.java`（3 接口 + Swagger）
- `InventoryService.java`（`importLogic` / `previewLogic` / `confirmLogic`，`confirm` 带 `@Transactional`）
- `AssetCodeMatcher.java`（纯 Java Levenshtein DP + 同义词热加载）
- `InventoryImportMapper.java` + `.xml`（`#{}` 防注入批量插入）
- `InventoryDiffJob.java`（每日 03:00 差异报表）
- `InventoryServiceTest.java` + `AssetCodeMatcherTest.java`（JUnit5 共 14 条）
- `README-接口文档.md`（Mermaid 时序 + 状态机）

`copilot-run --dry-print` 可先只打印需求文档，再看生成结果。

## 6. HTTP API（FastAPI，默认 :8080）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/health` | 健康与就绪态（Milvus/Redis/MySQL 状态） |
| GET | `/api/v1/prompts` | 查看 Prompt 模板清单 |
| GET | `/api/v1/rag/presets` | 预设演示问题 |
| POST | `/api/v1/rag/chat` | 问答（answer + sources + tool_calls + intent） |
| POST | `/api/v1/rag/chat/stream` | SSE 流式问答 |
| POST | `/api/v1/rag/import` | 上传文档灌库（MD/TXT/PDF） |
| POST | `/api/v1/copilot/run` | 跑 代码助手 生成代码（可带自定义需求文档） |

> 浏览器打开 `http://localhost:8080/docs` 即 Swagger UI，可点「Try it out」直接调试。

## 8. 常见问题（FAQ）

**Q：没配 LLM Key 能跑吗？**
能。每个 LLM 节点都有 fallback 模板，无 Key 时返回模板化内容，流水线 100% 跑通；填 Key 后自动切高质量模型。

**Q：一定要 Docker 吗？**
RAG 知识库 的向量检索需要 Milvus（Docker 起）；Q2/Q3 这类纯工具调用不依赖 Milvus。代码助手 完全不依赖任何中间件，首选零成本演示。

**Q：怎么接到公司真实 Spring Cloud 资产项目？**
1. 工具层替换：把 `rag_tools.py` 的 Mock 数据换成 MyBatis Mapper 查真实 MySQL，上层 LangGraph 0 改动。
2. 代码助手 产出落地：把 `output/copilot_XXX/` 的 Java 文件拷进 Spring Boot 项目 `src/main/java/`，改 package 即可编译（SQL 已防注入、事务已加回滚、锁带 finally unlock）。

**Q：怎么看效果指标？**
见 `README.md` 的「50 项评估指标」章节（RAG 知识库 30 条 + 代码助手 20 条），含召回率、响应时延、工具调用正确率、单测覆盖率等基准值。
