## 2. 推荐第一期：私活工作台与资料入口

从现有门户进入“私活工作台”，先能看清团队、资料和需求整理进度。复用 sihuo 的既有文件，不先复制整套源码和员工库。

建议界面范围：

- 工作室概览：当前服务方向、官网入口、待办事项及核验时间。
- 资料目录：服务说明、客户需求收集模板、工作室资料和宣传素材；内部资料与公开网站分开展示。
- 团队目录：岗位名称、职责、配置来源。只有执行器实际存在并可验证时，才显示启动任务功能。
- 需求草稿：录入客户提供的目标、平台、功能、预算和期限，标明缺失项，再与原有项目录入/解析能力衔接。

建议修改位置（均为后续实施候选，并非本次已创建）：

| 范围 | 候选位置 | 实施要点 |
| --- | --- | --- |
| 门户入口 | 现有 Portal/Home 与 `config/routes.ts` | 增加“私活工作台”；路径建议 `/subsystem/sihuo`，实施时按现有约定确定 |
| 工作台页面 | 现有 React 门户中新增对应页面 | 初期可直接做内部页面，是否独立服务按需求确定 |
| 资料读取 | 服务端专用索引/适配层 | 以 sihuo 中明确列入索引的文件为来源；浏览器不能仅凭 Windows 路径读取跨盘资料 |
| 岗位目录 | 读取已核实的员工清单与职责摘要 | 配置存在、可启动和正在执行分别表示 |
| 需求模型 | 现有项目接口适配或独立私活模型 | 先核对数据边界，不把企业审批阶段混成客户交付阶段 |

若后续选择嵌入独立服务，需同时核对 `SubsystemChrome`、`resolveSubsystemEntry`、登录约束、iframe 与网关配置；仅添加首页卡片不算完整接入。服务端读取文件也需明确可访问的资料范围，不开放任意路径读取。

## 3. 数据边界与建议字段

企业项目原模型具有编号、名称、负责人、日期、预算、目标等字段。它的 `draft/pending/approved/rejected` 代表立项审批，适合需求录入和确认，不足以表示私活业务全流程。

后续私活业务可按实际需求增加以下记录；这些是建议字段，不代表现有数据库已具备：

| 记录 | 最小字段 | 说明 |
| --- | --- | --- |
| 客户线索 | ID、来源渠道、客户称呼、需求摘要、跟进状态、下次跟进时间 | 联系方式按实际必要性保存，避免进入公开资料 |
| 需求草稿 | 项目名称、目标、平台、功能、资料依赖、预算范围、期望期限、待确认项 | 由用户或真实客户资料提供，不自动填造业务事实 |
| 报价草稿 | 范围版本、交付项、工作费估算、第三方费用、假设、有效状态 | 草稿与正式对外报价区分 |
| 客户项目 | 内部 ID、线索关联、负责人、需求版本、资料目录、交付状态、下一步 | 使用稳定 ID，不只按中文名称关联 |
| 里程碑 | 交付项、计划日期、实际日期、验收依据、付款记录关联 | 交付、客户验收和收款分别记录 |
| 岗位任务 | 任务 ID、岗位、输入资料、成果位置、执行状态、日志/证据 | 必须由真实执行器驱动状态，不能由静态配置假定执行成功 |

推荐先保留 sihuo 的 `projects/<项目英文短名>/brief.md` 等文档作为资料源，在结构化记录中保存稳定 ID 和目录引用。需要双向同步时，先明确字段由哪一侧维护，再实施冲突处理。

## 4. 第二期与第三期

第二期围绕一条真实或明确标识的演示线索，串起需求、报价草稿、任务计划、交付与验收。是否要付款节点和账款管理，应按实际业务需求决定，不在初期自动扩展为完整财务系统。

第三期再增加员工任务执行与宣传协作：

1. 选择执行方式，明确 project_agent 如何调用工作区已有岗位，以及任务的输入、输出、取消、失败恢复和日志位置。
2. 对接岗位任务状态与成果索引；启动配置、实际调用和成功完成分别验证。
3. 需要宣传视频时，从已核实的 sihuo 服务材料产生制作需求，由 animation-pro 生成独立标识的成片。
4. 如需进入发布服务，设计营销素材的分类、唯一 ID、重复发布保护与审批方式，避免借用技术栈 EP 集数覆盖已有发布状态。

现有 `python/douyin-auto/app/scanner.py` 按 EP 文件名扫描和去重；“有宣传脚本”不能直接推导成“已有可发布成片”。

## 5. 一期验收标准

- 从现有 `/portal/home` 可进入私活工作台，并正常返回门户。
- 展示的官网、资料和岗位来源可核对；路径不可访问时显示具体状态。
- 可以查看已选资料和整理需求草稿；官网生成 TXT 与后台实际接收线索分别说明。
- 现有员工仅按已验证的能力显示状态；没有执行接口时不出现假的“正在开发”或“测试通过”。
- 工作室网站和自建作品不会被统计为已成交客户项目；演示数据有明确标识。
- 原有项目管理和抖音发布入口仍正常，视频扫描契约保持兼容。
- 采用远程门户时，资料读取、静态资源、网关与登录范围实际验证通过。
- 实施后更新 `PROJECT_MAP.md`，写明已完成范围、验证证据、未完成事项。
