# 企业资源管理平台 · 财务（FIN）模块手册 v1.8

> **文档归类**：FIN 模块 · 操作手册 · 2024-12 账期
> **适用对象**：财务共享中心、出纳、报表会计、业务部门预算接口人
> **关联单据编码前缀**：`FIN-INV-`（发票/报销）、`FIN-PAY-`（付款单）

## 1. 模块概览

财务模块承载 **从单据 → 凭证 → 账 → 报表** 的全链路。核心四类单据：

| 前缀 | 单据类型 | 谁发起 | 谁审批 |
| --- | --- | --- | --- |
| FIN-INV- | 发票录入（专票/普票） | 应付会计 | 财务经理（孙丽华） |
| FIN-INV- | 报销单 | 全员 | 经理 → HRBP → 财务出纳 |
| FIN-PAY- | 付款单 | 应付会计 | 孙丽华 + 资金组双审 |
| FIN-CLS- | 期末结账凭证 | 报表会计（赵天宇） | 孙丽华 |

本演示内置的 4 条真实对应单据（与 `query_resource_by_code` 工具的 Mock 数据一致）：

| 单据编码 | 类型 | 金额（元） | 收款方 | 付款方 | 账期 | 状态 |
| --- | --- | --- | --- | --- | --- | --- |
| FIN-INV-2024-001 | 增值税专票 | 182,600.00 | 联想（北京）有限公司 | 本公司-主体A | 2024-12 | 已入账 |
| FIN-INV-2024-002 | 报销单 | 4,820.50 | 陈昊（员工报销） | 本公司-主体A | 2024-12 | 待审核 |
| FIN-INV-2024-003 | 增值税普票 | 374,400.00 | 戴尔（中国）有限公司 | 本公司-主体A | 2024-11 | 已入账 |
| FIN-PAY-2024-117 | 付款单 | 140,250.00 | 华为技术有限公司 | 本公司-主体A | 2024-12 | 已入账 |

### 1.1 与其他模块的联动

- **资产模块入库 → FIN 自动生成凭证**：如 `FS-2024-1021` 戴尔服务器入库 8 台 × 46,800 = 374,400 元 →
  对应 `FIN-INV-2024-003`（本手册 2.3 有完整分录）。
- **HR 模块发薪 → FIN 批量 FIN-PAY**：每月 10 日出工资条，15 日付款。赵天宇每月 5 日起做薪资预提。
- **RAG + Agent 联动**：报表会计赵天宇日常用知识库 Agent 问"**联想 2024 年 12 月专票合计多少？**"
  → Agent 调 `fuzzy_match_resource(keyword="联想", module="FIN")` + 聚合金额 → 再 `export_to_excel`。

### 2.1 增值税专票（示例：FIN-INV-2024-001）

典型场景：行政采购了 14 台联想工作站 FS-2024-0876，总价 14 × 12,800 = **179,200 元 + 税 3,400 = 182,600 元**。

| 字段 | 值 |
| --- | --- |
| 发票号 | FIN-INV-2024-001 |
| 开票日期 | 2024-12-12 |
| 销方 | 联想（北京）有限公司 |
| 税率 | 13% |
| 不含税金额 | 179,200.00 |
| 税额 | 3,400.00 |
| 价税合计 | 182,600.00 |
| 状态 | 已入账 |
| 对应采购 | 14 台 FS-2024-0876 工作站 |
| 入库批次 | BATCH-ASSET-202412-003 |

入账分录（SAP/金蝶通用）：
```

借：应交税费-进项税       3,400
  贷：应付账款-联想         182,600
```

## 3. 报表与结账

### 3.1 月结 Checklist（赵天宇每月执行）

| 日期 | 动作 | 产出物 |
| --- | --- | --- |
| D-3（每月倒数第3天） | 预提工资/税费/折旧 → 草稿 | 《预提计算表.xlsx》 |
| D-1 | 资产模块与 FIN 对账（FS × FIN-INV 勾稽） | 《资产-FIN 差异表》（Agent 自动 export） |
| D+0 18:00 | 孙丽华点"结账"按钮 | 账期关账 |
| D+2 | 赵天宇出 3 表：资产负债 / 利润 / 现金流量 | 上报集团 |

### 3.2 常见对不上的情况 + Agent 处理方式

1. **资产金额 ≠ FIN 金额**：Agent 先查 `FS-2024-xxxx` 编码 → 金额与 `FIN-INV-xxxx` 是否一致；
   不一致 → 调 fuzzy 工具找"最接近的 FIN-INV" → 人工复核（对应 interrupt/HITL）。
2. **报销重复入账**：`query_resource_by_code(FIN-INV-2024-002)` 重复提交 → Agent 走 export_to_excel
   生成《疑似重复报销清单》→ 推孙丽华。

## 4. 合规红线

> 知识库 Agent 在做 RAG 知识库时，我特意把"合规红线"章节 chunk 单独加权重，
> 保证 LLM 回答"能不能给陈昊重复报销"这类问题时 100% 命中合规条款，不会出现幻觉。

- **红线 1**：一张发票只能对应一张 FIN-INV，严禁"一码多用"，违者触发二级合规调查。
- **红线 2**：单张报销 > 5 万元必须财务总监孙丽华 **手工面签**，系统不允许跳过。
- **红线 3**：付款单 FIN-PAY 一律"双人复核"（资金组 + 孙丽华），系统内硬卡单人无法提交。
- **红线 4**：年底关账（D+0 18:00）之后禁止反结账，需走「集团财务副总裁特批」单。
